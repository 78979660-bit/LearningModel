已准备 `tools/accept_release_0_1_1.ps1`，针对既有 0.1.0 验收虚拟机执行升级、静默卸载保留数据、重装、数据库哈希及记录计数核对，并另测干净用户配置。`tools/clean_windows_acceptance.ps1` 已支持版本参数及本轮校验文件，可用于独立干净机器。

LearningModel-QA 虚拟机接入最初返回 `guest execution service is not ready`，截图也失败。用户授权重启后已恢复 Guest Control；Windows 系统事件还记录了操作系统升级触发的计划内自动重启。

首次升级实测：0.1.0 基线程序自检成功。0.1.1 安装器复制了程序文件，但创建当前用户卸载注册表项时 `RegCreateKeyEx` 返回错误 5（拒绝访问），安装器退出码为 4 并执行回滚流程。回读显示程序文件版本为 0.1.1、卸载注册项不可见，故不能认定安装成功，也不能认定旧程序已完整恢复。

随后只读检查确认：`InteractiveUser=null`、测试用户 `HKEY_USERS\SID` 未加载；普通 `HKCU\Software` 测试键也不可写。该执行会话不满足当前用户安装的环境条件，不能据此认定安装器在正常登录桌面中同样失败。验收脚本已增加用户配置加载及注册表写入预检，在上述条件下会于安装前停止。

原始测试数据库及备份留在虚拟机。首轮备份取于基线自检前，后续数据库字节哈希与其不同；不能据此判定学习数据丢失或宣称数据保留通过。后续脚本已改为在基线自检后备份并保存安装前哈希。基线恢复工具及已校验的 0.1.0 安装包已在虚拟机验收目录准备；正常登录 qauser 桌面后，先恢复并核对数据哈希，再重新运行完整生命周期验收。
