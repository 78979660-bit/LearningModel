# PySide6 + Qt Quick/QML 分阶段迁移审查

## 基线与结论

- 审查基线：`main`，HEAD `f8a4d4a`（标签 `v0.1.1`）。开始审查时工作区干净，项目中没有 QML 或 QRC 文件，也没有项目级 `AGENTS.md`；Windows 侧规则按用户提供的 `USER_HOME\.codex\RTK.md` 执行。
- 本次迁移分支：`codex/qml-washi-phase1`。保留当前 Widgets 启动链作为回归对照，第一阶段提供可单独启动的完整 Qt Quick 窗口。
- 现有服务和数据层已经覆盖学习计划、记录、知识图谱、助理、练习题、学科目录和可恢复生命周期。主要迁移成本集中在界面耦合：Widgets 页面直接读取设置、调用存储仓储、持有业务状态并编排后台任务；主窗口还负责路由、主页装配、菜单动画、系统托盘与刷新生命周期。
- 第一阶段不把其他路由的占位内容计为迁移完成。主页必须绑定隔离测试数据库产生的真实快照；其余菜单项只作为清楚标明“待迁移”的真实数据摘要路由。

## 当前入口与界面盘点

逐调用点清单见 [QML_UI_INVENTORY.json](QML_UI_INVENTORY.json)，由 `tools/inventory_widgets_ui.py` 解析未改动的 Widgets 源码生成，列出页面工厂、Qt 类、所有已识别的弹窗/菜单调用点、工作器/任务提交点与直接服务调用（含文件、行号和所属函数）。静态调用点不等同运行可达性，闭包中服务对象的方法仍按下文人工审查补充。

### 启动和主路由

- 发布启动入口是根目录 `run_study_app.pyw`；源码入口还支持 `python -m study_app`，最终经 `study_app/main.py` 到 `study_app/ui/app_runtime.py:run_app()`。
- Widgets 运行时在 `app_runtime.py` 创建 `QApplication`，完成单实例、用户目录和种子数据库初始化、可选能力诊断、托盘与每周采集线程管理，再创建 `window_shell.py:create_main_window()`。
- `ui/window_shell.py` 的 `QStackedWidget` 有五条实际主路由：主页（0）、学习计划（1）、学习助理（2）、知识图谱（3）、设置（4）。同一动态类还实现导航栏折叠动画、自动窄窗折叠、数据刷新、状态栏、托盘菜单、隐藏到悬浮图标和恢复窗口。
- `ui/main_window.py` 是仍被发布自检及兼容代码引用的旧模块；不能因新增 QML 入口而删除或悄悄改写。Widgets 入口应继续可运行，直到新入口通过各阶段验收。

### 弹窗、菜单和需要保留的交互

- 学科管理：`ui/subject_management_dialog.py` 从助理页的显式“学科管理”入口打开；目录可从本地 TXT、Markdown 或限定结构的 JSON 填入草稿。选择或编辑任何内容都会使旧预览失效。
- 学科管理预览要求用户查看影响清单、勾选确认，并准确输入学科全名后才能执行。执行中锁定表单并阻止关闭，实际写入由 QThread 完成。
- 助理提供附件文件选择器、建议操作确认框，以及错误和结果反馈；学习计划有复习模式等配置对话框及多处失败/完成反馈；记录编辑器有材料选择和输入校验反馈；设置页有备份和配置反馈；知识图谱有图例弹窗。
- 主窗口提供系统托盘菜单和悬浮图标上下文菜单。迁移应保留易发现的菜单入口、键盘可达性和可读名称，不将菜单项画进不可访问的背景图。

### 后台任务与业务服务

- `core/async_tasks.py:AsyncTaskService` 是基于 `ThreadPoolExecutor` 的通用执行池，支持键去重、取消/超时后的结果丢弃、generation 过期门控，以及学科目录修订/对象版本二次校验。现有 UI 多用短间隔 `QTimer` 轮询 `TaskHandle`。
- 主页刷新从 `window_shell.py` 通过单线程 `AsyncTaskService` 调 `core.dashboard.load_dashboard_state()`；每日 LLM 总结在 `dashboard_widgets.py` 的独立服务中运行。
- 学习助理在 `query_page.py` 使用并行工作池执行查询、提案预览、执行和撤销；记录识别在 `record_editor.py` 使用工作池；设置页用工作池执行备份和完整性检查；章节图谱用工作池加载投影。学习计划在 `study_plan_page.py` 将计划生成与 ChatGPT PDF 工作流包装成 QObject/Signal，并由其自行创建后台 `threading.Thread`；这些类不是 QThread，不能复用其中对 Widgets 回调的假设。
- 学科管理的提交操作也使用 QThread。应用启动时的 `WeeklyCollectionWorker` 是独立 `threading.Thread`，仅在用户打开对应设置且采集到期时运行；应用退出时请求停止并有限等待。
- `data/`、`core/`、`ai/` 及 `integrations/` 承载真实业务与持久化接口。迁移不重写算法，不让 QML 访问 SQL、文件路径、API 凭据或直接拼接仓储操作。所有耗时读取/写入由 Python 界面适配层放入工作线程，结果通过 Qt 信号回主线程更新。

### 主页可复用的真实数据接口

- `core.dashboard.load_dashboard_state()` 返回 `DashboardState`，包括日期窗口、标杆、学科摘要、待办、遗忘风险、BKT 预警、数据源诊断等。它已通过现有 SQLite 与兼容读取路径计算主页业务数据，直接把整个对象传到 QML 会同时暴露内部原始记录和模型字段。
- `ui.activity_view.filter_homepage_activity(state)` 使用 `core.active_subjects` 过滤归档学科的首页活动；`core.active_subjects.active_subjects()`、`active_subject_names()` 是活动范围的权威过滤规则。页面 DTO 不应自行重写生命周期判断。
- 今日安排读取应通过 `data.plan_repository.get_budgeted_day_plan()` 和 `get_active_study_plan()` 等现有查询接口。现有 `design_components.today_plan_card()` 会直接访问数据库兼容门面，QML 适配层应改为明确调用仓储/服务，避免把数据库访问放进 QML。
- 建议首页界面接口为 `HomeDashboardAdapter(QObject)`：公开只读的 `homeData`、`loading`、`error` 属性及 `refresh()` 槽；任务完成、失败和数据更新经 Qt signal 回到 GUI 线程。适配器在 Python 内调用以上服务，转换为白名单、可序列化的首页 DTO（例如日期范围、四项计数、活动学科行、今日计划摘要和下一项、待办行、风险行、数据源状态），不返回 `raw_records`、`model_data`、密钥、SQLite 连接或本机绝对路径。
- 第一阶段主页是只读的；刷新只能重新取数和替换 DTO，不写学习记录、计划、设置或密钥。首屏取数也不能阻塞 GUI。LLM 凭据加载与 LLM 请求不属于第一阶段接口。

## 耦合问题与迁移约束

1. `window_shell.py` 将窗口生命周期、页面装配、主页数据格式、折叠菜单状态、托盘和后台刷新放在一个动态生成的 QMainWindow 类中；主页刷新还会逐个重建动态卡片。QML 侧应拆成窗口/路由、主题组件和 Python 用例适配层。
2. Widgets 页面普遍通过闭包共享临时状态、控件对象和服务句柄，业务动作与 `QLabel`、`QMessageBox`、`QFileDialog` 紧邻。跨页数据更新靠 `_set_dashboard_state` 等约定式方法，而非统一接口。
3. 当前主页及设置、助理和计划页直接加载设置或业务模块；部分主页组件经 `data.database` 门面读计划或写缓存。若把这些调用复制到 QML slot，会形成新的 UI 到数据库/密钥耦合。
4. 现有线程服务与界面适配约定并不统一：有线程池 + 定时轮询、学科管理 QThread、计划页自行封装的 `threading.Thread`、启动期同步计算和后台采集线程。迁移时要为每个 QML use case 指定所有者、取消/关闭规则、失败状态与过期结果策略，所有阻塞 I/O 与重计算都不能在 GUI 主线程。
5. 现有 QML 资源目录、资源清单和 QML 启动自检都不存在。只在开发目录直接加载 `.qml` 会导致源码可运行而 PyInstaller 发布包缺资源或 Qt Quick 插件，必须将资源打包和离线自检纳入验收。
6. `DashboardState` 含内部字段，Widget 测试使用的实例和隔离数据库也不应直接复用为 QML 对外协议。适配层要定义稳定数据合同、错误语义和可测试的数据库路径注入点。
7. 视觉概念包仅用于色彩、纸感和装饰方向。纸纹、樱花、竹叶分别作为素材层，图标和内容文字保持向量/真实控件，布局适应字体缩放、窗口缩放、高 DPI 和键盘焦点。

## 目标目录结构

保留 `study_app/core/`、`study_app/data/`、`study_app/ai/` 和 `study_app/integrations/` 为领域/数据服务层。Qt Quick 代码集中在 `study_app/quick/`，Widgets 代码继续留在现有 `study_app/ui/` 中，避免同一页面跨目录拆分。第一阶段具体落点为 `study_app/quick/{__main__,runtime,bridge,dashboard_service,resources,self_test}.py` 与 `study_app/quick/qml/{Main,Theme,qmldir,components,pages,assets}`。

建议增量结构：

- `study_app/quick/__main__.py` 与 `runtime.py`：QGuiApplication、engine、独立入口、退出清理和根对象校验；不得调用旧的 `create_main_window()` 或创建 QWidget。
- `dashboard_service.py`：调用既有本地服务并投影白名单 DTO；`bridge.py`：对 QML 暴露清晰属性/槽，把异步结果派发回 GUI 线程；后续按用例增加计划、记录、助理、知识、设置和生命周期适配器。
- `resources.py`：集中资源 URL 与资源清单；`self_test.py`：源码/冻结启动自检。QML/import 资源按文件白名单加入发布包，不采用或暗示使用 QRC。
- `quick/qml/Main.qml`、`Theme.qml`、`qmldir`、`components/`、`pages/`：应用根、统一颜色/间距/字体/缩放令牌、通用按钮/卡片/导航、具名页面与路由。
- `quick/qml/assets/`：独立纹理、樱花/竹叶装饰、图标等源素材；资源文件清单随应用代码维护，不把整张概念图作为背景。
- 重复数据集只有在稳定增量更新有需要时才实现 QAbstractListModel；其他数据使用只读 DTO，避免把业务模型直接暴露到 QML。
- 根目录保留现有 Widgets 启动入口；增加明确的 QML 源码入口和 QML 自检参数/命令。发布入口何时切换放在阶段五，避免第一阶段影响旧 UI 回归路径。

## 分阶段迁移顺序

### 阶段 0：审查与基线

- 完成当前分支、工作区、启动入口、页面/弹窗、后台任务、真实业务服务、主路由和学科安全流程盘点，记录在本文。
- 固定基线 `main f8a4d4a` 与目标分支 `codex/qml-washi-phase1`；保留既有用户修改，变更前后核对 git status/diff。
- 验收：文档准确标记五个当前路由与未接入的叶子页面；运行旧 Widgets 路径及现有相应契约测试时不因审查方案发生改变。

### 阶段 1：完整 QML 框架、只读真实首页与菜单

- 建立独立 QML 启动路径、单一根窗口、主题令牌、可复用卡片/按钮/导航组件和具名路由；不在 QML 窗口内嵌 QWidget。
- 实现主页真实只读快照：活动学科、窗口评分与掌握摘要、推荐/风险计数及详情、今日预算计划/下一项、刷新时间和明确的加载/空数据/失败状态。数据来自既有 Python 服务与隔离测试库。
- 首屏加载和刷新都在后台执行；按请求 generation 丢弃旧结果；QML 仅绑定 DTO 和调用公开 slot。首次运行时，QML 入口只在工作线程执行用户目录和种子数据库初始化；之后每次主页刷新严格只读。不得复用会调用 `load_llm_settings()` 的 Widgets 初始化，不读 API 凭据、不请求 LLM、不提供会写学习数据或设置的操作。
- 阶段一明确不迁移主页的 LLM 模式切换、AI 每日总结、浮窗图标或托盘交互；新主页只呈现本地只读服务数据。这些旧首页功能仍由 Widgets 路径保留，不因外观相似而记为已迁移。
- 第一阶段将 QML 根页面、组件、图标/独立装饰素材及 `qmldir` 按文件白名单加入资源打包，并扩展冻结启动自检以验证 QML 根对象和资源可加载。该阶段完成的是资源打包与自检基础；完整安装包验收和常规发布入口切换留在阶段五。
- 主页主菜单支持从首次收起状态进入、展开、反复收起/展开；菜单项保持真实文本可访问名称、提示与键盘焦点。四个尚未迁移的路由可展示基于真实服务快照的简短摘要和明确“待迁移”状态，不显示空白页或样例演示，也不得把它们标成迁移完成。
- 主题使用真实文本和可访问控件；概念图只供构图参考，装饰拆为纸纹、樱花、竹叶等独立可缩放素材。
- 验收：以隔离数据启动新 QML 窗口并得到真实数据；刷新反映测试库的改变；首页读写边界可审计；主线程无数据库读取/模型重算；首次菜单收起、反复开合、路由切换、不同窗口宽高、DPI 和键盘导航均有自动化或可重复手工记录。Widgets 旧入口仍可启动。

### 阶段 2：学习计划、记录、OJ 与 PDF

- 迁移计划、记录、OJ 三条用例，再连接本地练习卷/PDF。原计划中的 ChatGPT 桌面 PDF 工作流已按用户 2026-10-05 的要求从当前分支删除，不再列入后续验收。
- 沿用 `study_plan_page.py`、`record_editor.py`、`oj_page.py` 背后的 core/data 服务和校验。预算确认、计划持久化、记录识别后的复核再保存、OJ 显式题目/知识点映射均保留既有确认语义。
- 估时、生成、附件提取、OCR、本地 PDF 生成等操作运行于后台；取消、超时、关闭和过期结果遵循服务现有约定。失败时恢复按钮状态并保留可理解错误。桌面 ChatGPT PDF 自动化已按阶段四要求删除。
- 验收：隔离数据库端到端验证计划读写、记录新增/识别确认、OJ 题目与提交、PDF 文件输出；真实窗口下可从主路由到达这些功能，且旧 Widgets 页面行为继续可作对照。

### 阶段 3：学习助理、图谱与预警

- 迁移本地问答/可选 LLM 增强、附件、建议提案、审批执行与撤销、自动执行策略、知识图谱阅读/节点选择、预警列表/处理/延后。
- QML 调用 Python 适配器；LLM 设置与密钥由 provider 服务读写，QML 不持有密钥。可能改变学习数据的助理建议仍需显示操作预览并等待用户确认，保留撤销和事件审计。
- 将 graph view 从 QWidget 特定的 `chapter_graph_view.py` 抽取为可供 QML 使用的投影/布局数据和 QML 可缩放画布表现；预警查看与操作复用现有 core/domain 服务，不复制判定规则。
- 验收：验证无密钥本地模式、LLM 受限错误状态、建议取消/确认/执行/撤销、图谱缩放和选择、预警处理/延后与审计；后台请求关闭或数据版本变化时不能应用旧结果。

### 阶段 4：设置与学科生命周期安全操作

- 迁移备份、provider/隐私/预算/助理策略、审计及能力状态；敏感设置只经 Python 服务执行，页面对凭据只显示安全状态，不把密钥送入 QML 属性或日志。
- 迁移学科目录管理，但完整复用 `core.subject_management.list_subjects()`、`prepare_management()`、`execute_management()` 和现有仓储/changeset 机制。
- 引入必须由用户提供且校验的章节/知识点目录；移除只能归档，必须先显示关联记录、活动/共享计划等影响；恢复必须使用原稳定 subject_key 与保留身份。写操作仍要求显式预览、确认勾选、准确输入完整学科名、变更期间锁定，并先成功创建和校验 SQLite 备份。
- 保留 revision/object version 检查、关联影响指纹复核、原子事务、幂等操作、目录投影失败可重试行为；失败不静默成功，不删除学习记录，恢复时不重新激活旧计划。
- 耗时备份/投影/执行在工作线程运行；适配器只调用现有 service，不让 QML 直接 SQL 或重造安全规则。
- 验收：在隔离测试数据库覆盖引入、重复名拒绝、预览后数据漂移、备份失败回滚、移除保留记录与归档计划、恢复原身份、重复执行幂等、投影待重试；旧安全弹窗保持可作回归对照直至该阶段通过。

### 阶段 5：资源打包、自检与发布入口切换

- 完成 QML 与 import 资源白名单、Qt Quick/QML 引擎及 import 插件在冻结安装包内的完整验收。发布 spec 不采用整个项目递归打包，继续沿用受控资源清单，防止个人数据进入安装包。
- 扩展启动自检：在临时用户目录/隔离数据库下初始化 QML runtime、加载根窗口与每条路由、检查资源 URL/图像解码和 required imports，并输出机器可读结果；自检不读取真实用户数据或密钥，所有首次初始化都局限于临时目录。
- 运行 Windows 源码启动、冻结目录启动、隔离数据库自检和旧 Widgets 启动对照；确认 DPI、素材、翻译、托盘/退出生命周期和 QML 错误日志。
- 只有阶段 0–5 验收清单完成后才将常规入口切到 QML；保留显式 Widgets 对照入口和回退方式。任何未迁移页面继续明确标识，不能以成功启动或出现菜单为全应用迁移完成。

阶段五实现与验收记录见 [QML_PHASE5_ACCEPTANCE.md](QML_PHASE5_ACCEPTANCE.md)。本阶段补齐首页每日总结及模式开关、浮窗恢复、托盘/明确退出生命周期；资源诊断与正式 Python 3.14.5 QA 构建已接入。常规入口切换仍服从上面的验收条件，历史阶段记录不随新增功能改写为全应用验收通过。

## 跨阶段验收标准

- 数据：首页来自项目真实计算服务和隔离测试数据；至少两份不同 fixture 能显示不同值，执行刷新可看到新状态。没有把视觉概念图中的示例数值、功能或文案当成产品需求。
- 边界：QML 资源、字符串绑定与交互回调中没有 SQL、数据库连接、密钥、绝对用户路径；适配器 DTO 只暴露页面所需字段。
- 响应：任何 DB、文件、OCR、AI、网络、PDF、备份与模型重算均不在 GUI 主线程；路由切换和菜单动画期间窗口持续响应；旧/过期任务结果不会覆盖新状态。
- 导航和可访问性：初始菜单状态经实际窗口尺寸规则验证；多次切换无宽度跳变/失焦/状态漂移；路由变更高亮正确；Tab/Shift+Tab、Enter/Space、可见焦点、AccessibleName、缩放字体均可用。
- 尺寸/DPI：小/中/大窗口与 100%、150%、200% 缩放下卡片重排、文字换行、菜单图标和装饰边界正确；纸纹等素材不承载信息。
- 维护和回归：业务规则仍位于 core/data/ai；每次迁移后运行相关既有契约测试和新 QML 行为测试；旧 Widgets 入口与主题契约在阶段五前继续验证。
- 包装：QML、图像、字体（若新增）和 Qt Quick import 模块都由资源清单显式进入冻结包；启动自检能在无可写源码目录的临时配置下加载全部主路由。

## 第一阶段实现边界

第一阶段的迁移完成范围只有完整 QML 窗口框架、主题与共享组件、五项菜单路由、真正绑定实际服务的只读首页、可刷新/异步加载状态和菜单展开/收起。学习计划、助理、图谱、设置、记录、OJ、预警和生命周期页面仍由 Widgets 或标记为待迁移的真实数据摘要路由承载，不能宣传为 QML 迁移完成。学科安全流程继续由现有 Widgets 对话框和 Python service 保持可用，直到阶段四的完整 QML 用例通过验收。

## 阶段二增量

阶段二学习计划路由接入了计划、记录、OJ 与练习 PDF 四个实际工作区页签，使用独立、显式路径注入的 Python 用例服务；首页接收写入后的真实刷新。上述边界记录各阶段当时的基线，阶段二实现与验证见 [阶段二验收](QML_PHASE2_ACCEPTANCE.md)。

## 阶段三增量

学习助理与知识图谱路由接入了真实服务：本地只读问答、可选外部补充、附件建议、审批/拒绝/重新预览/撤销、执行策略与审计，以及章节图谱、知识证据、预警处理与延后。新页面继续使用完整 QQuickWindow；QML 只接收 DTO 与调用固定用例，所有 I/O 和业务提交由后台 Python 适配层执行。当时范围、验证记录和未验收的外部链路见 [阶段三验收](QML_PHASE3_ACCEPTANCE.md)。阶段三不代表全应用迁移或正式发布完成。

## 阶段四增量与范围调整

设置路由新增真实 provider/隐私/预算/助理策略配置、LLM 审计、数据库备份与完整性检查；学科管理提供目录输入或本地文件填入、影响预览、完整名称与勾选确认、引入、归档移除、恢复、能力与生命周期审计以及目录投影重试。写入复用原核心服务，保留备份校验、版本与关联影响复核、稳定身份、原子事务及幂等机制。凭据通过 Python 管理的 Windows 系统输入框配置，QML 不接收密钥文本。

按用户要求移除 ChatGPT 桌面 PDF 生成及其退出清理、脚本、接口和打包依赖；保留本地练习 PDF、普通练习提示词与手动复制上下文，不再要求桌面 PDF 端到端验收。原审查和阶段一至三验收文档中的桌面流程条目是历史记录。

五条主路由现在都有实际 QML 页面和真实服务；仍保留 Widgets 回归入口，托盘/浮窗、首页每日 AI 总结、正式 Python 3.14.5 发行与外部 AI/OCR 端到端验收不属于本阶段完成范围。阶段四验证与限制见 [阶段四验收](QML_PHASE4_ACCEPTANCE.md)。
