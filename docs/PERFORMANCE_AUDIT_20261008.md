# 2026-10-08 交互卡顿与重复加载排查

## 结论

本轮发现的主要开销是同步创建 QML 控件、隐藏区域提前创建大量控件、进入页面重复计算，以及所有业务共用单个工作线程造成的排队。本轮探针未观察到死锁；没有依据认为字体字号、纸纹强度或图谱节点尺寸是主要原因。保留画质与串行写入顺序，没有通过增加线程数掩盖问题。

## 方法与范围

使用上轮关闭应用时的本机数据备份，在独立目录复制 SQLite/模型/记录后测试，没有操作当前学习数据。CPython 3.14.5 / Qt 6.11.1，Windows 原生窗口 1280×850。对后台任务逐个使用 cProfile；16 ms Qt 定时器记录 GUI 事件循环间隔，连续两轮切换五个页面。记录不调用云端模型。

原始日志：`output/perf-before-20261008/` 与 `output/perf-final-20261008/`，探针脚本 `output/profile-interactions.py`。cProfile 会增加运行开销，下表用于同一探针下的比较，不是无 profiler 的用户端帧率。前后各一轮，不能视为统计置信区间。最终复测与测试/构建错开运行。`settle_ms` 包含固定等待，不用于下表。

## 第三轮：进入页面后的波动与重复读取

再次在本机安装版复现：首次计划页先展示“暂无活动学科”，再被任务列表撑高；重访虽然保留了计划/助理实例，仍会进入忙碌状态、禁用并恢复表单。其他顶层页面依然重建，助理数据通知也会触发图谱绑定重新求值。

本轮完成：
- 五个顶层页面均首次访问才创建，之后保留。离开时仍执行原有预览失效逻辑，关闭设置与助理弹窗，不复用复核授权。
- 新增后台页面新鲜度检查：在原串行工作队列中读取日期及数据库、WAL、journal、模型、记录文件的元数据；数据未变化不运行整页加载、不切换 busy、不重置表单。显式刷新仍强制读取，日期/外部文件变化会重新读取。读取过程中源文件变化不会认证该快照。该机制只控制展示刷新，业务操作仍走原服务的权限、版本、令牌与确认校验。
- 计划、助理、图谱分别发送数据通知，避免不相关数据变化连带重建其他页面。设置读取相同数据时也不再重置输入。
- 计划任务改用固定高度 ListView，只创建可见行及小量缓冲，滚动查看完整列表。首次无数据时显示读取状态，不提前宣称没有学科。
- 计划子页面按需异步加载，保留内容区占位，待 Loader.Ready 后才显示完整控件。自检与 UI 自动化也等待实际就绪，避免操作半成品控件。修复自检异常清理时 lifecycle 尚未创建的空引用。
- 加载指示器保留固定位置，不再挤动标题和刷新按钮。
- 助理操作历史与可撤销状态改用单次只读事务读取各自的条目集合，保留索引顺序和原筛选逻辑，消除逐条重连数据库的开销；不缓存授权或撤销令牌。
